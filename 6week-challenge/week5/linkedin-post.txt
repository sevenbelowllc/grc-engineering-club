"Security Hub gave me zero findings. For 45 minutes."

Not "still loading." Zero — and it would have stayed zero forever.

I was standing up AWS Security Hub with the NIST 800-53 baseline for a GRC chain-of-custody project. Enabled it, subscribed the standard, waited. Nothing. Every standard sat INCOMPLETE, reason: NO_AVAILABLE_CONFIGURATION_RECORDER.

Here's the nuance, and it's the whole lesson:

→ Security Hub is a REPORTING layer, not a sensor. It does not inspect your resources directly. It reads the resource state that AWS Config records.

→ No Config recorder means no data to grade. The checks can't run, so nothing comes out — not even the "AWS Config should be enabled" finding. The dashboard that's supposed to tell you Config is off can't tell you anything, because it needs Config to tell you.

The guidance I was following called Config "optional." For a fresh account, it is a hard dependency. Turn on the grader without the sensor and you get a confident, empty, green-looking dashboard — which is worse than no dashboard, because it looks like coverage.

So the honest version of "I enabled continuous monitoring" isn't "I turned on Security Hub."

It's: "I turned on the sensor (Config) AND the grader (Security Hub), and I confirmed the grader was actually receiving data before I trusted a single finding."

That last clause is the GRC discipline. A control that's ON is not the same as a control that's WORKING. The gap between them is exactly where an empty dashboard hides.

I added Config in Terraform, and findings populated in 30 minutes. First critical finding? Config.1 — flagging that my own Config setup used a custom role instead of the service-linked one. The pipeline caught me. That's it working.

Native controls captured, signed into the same chain of custody as my Terraform plan, torn down the same day. Pennies.

Verify a control is producing data before you report on it. "On" is a claim. "Producing evidence" is a control.
